# Шаблоны Excel / CSV

Первый вариант: один необязательный report_template на сценарий, одна таблица
источника, один лист Excel. Текст сценария остаётся инструкцией модели для
выбора шаблона и параметров. SQL, Python, формулы Excel пользователь не вводит.

## Настройка в APEX

В «Сценарии: создание / изменение», под таблицами появился блок
«Шаблон Excel / CSV». Он доступен только администраторам как и сам редактор.

1. Выберите таблицы сценария и отметьте разрешённые поля.
2. Включите шаблон, нажмите «Обновить поля из выбранных таблиц», выберите источник.
3. Укажите имя файла, формат, лист и параметры (поле, подпись, обязательность,
   значение по умолчанию). Можно добавить постоянные фильтры.
4. Добавьте колонки в нужном порядке: заголовок, уникальный ключ,
   операция и поля. Ключ нужен для ссылок расчётов друг на друга.
5. Выберите форматы значений, денежные колонки, ширины, итоги и сортировку.
6. Сохраните сценарий. В чате попросите сформировать файл по этому сценарию.

Источник и колонки выбираются из доступных таблиц сценария. API повторно
проверяет структуру шаблона при сохранении, включая частичное обновление сценария.
Убрали таблицу/колонку, используемую шаблоном — сначала измените/отключите шаблон.

Пример готового сценария: examples/institutions_template.json.
Он использует oracle_data.zv_gpt_organizations: organization, jurpers,
organization_name. Формирует колонки «№», «Учреждение», сортирует по названию.
Параметр jurpers обязателен, в том числе для администратора. Версии в этом
справочнике нет; шаблон не притворяется, что может фильтровать её.
Пример можно создать POST /api/scenarios через действующий административный API
или повторить настройки в форме. Файл-пример сам по себе ничего не создаёт в БД.

## Расчёты

- field: поле источника, текст/число/процент.
- row_number: номера после сортировки.
- sum/count: сумма/количество, дополнительно условие «поле входит в список».
  count без field считает все строки; с field — только непустые значения.
- difference: разность двух предыдущих числовых показателей.
- ratio/percent: отношение двух предыдущих показателей.
  Для процентного отображения хранится доля (0.25), Excel показывает 25%.
- Нулевой или NULL знаменатель: «—». Пустые наборы условной суммы дают 0;
  набор только из NULL даёт «—», чтобы не скрывать отсутствие значений.
- Числа вычисляются Decimal. Исходные строки не переписываются моделью.
- При агрегатах группировка включает все field-колонки и дополнительные group_by.
  Для одноимённых учреждений укажите ID учреждения в group_by.
- distinct удаляет одинаковые строки обычного списка; с агрегатами он запрещён.
- Строка итогов выводит отмеченные показатели. Разности/отношения вычисляются
  заново из итогов зависимых показателей, проценты не складываются.

Масштаб «тыс./млн/млрд» действует только на колонки с флажком «Денежная сумма»;
количество, годы и обычные числа не масштабируются. Масштабирование — при выводе,
в вычислениях остаются исходные значения. Единицы добавляются в заголовки
денежных колонок и одинаковы в файле и предпросмотре.

## Выполнение

Модель вызывает create_template_report с scenario_id, параметрами и
необязательным выбором xlsx/csv. Колонки, условия, операции и оформление изменить
через этот инструмент нельзя. Неизвестные/пропущенные обязательные параметры —
ошибка инструмента; модель должна уточнить их, а не игнорировать.

Сервер использует те же проверки активного сценария, разрешённых таблиц/полей,
is_admin, visible_jurpers и области jurpers/jur_pers + organization, что query_scenario.
У администратора область шире; обязательные параметры шаблона помогают задать
конкретное юрлицо. Постоянные фильтры, параметры и область пользователя соединяются AND.

Для шаблонов отдельный серверный предел MAX_TEMPLATE_ROWS (50 000 исходных строк).
Лимит 200 строк инструмента анализа к этому пути не применяется. Получается ещё
одна строка для проверки полноты; при превышении экспорт отменяется, без усечения.
MAX_TEMPLATE_BYTES (5 МиБ) ограничивает размер готового файла.
Оба значения в settings.toml. Таймаут чтения источника — текущий таймаут query_scenario.

После создания шаблонного файла сервер сам возвращает количество строк,
первые 10 строк того же результата и реальную ссылку. Модель не переписывает
эту финальную выдачу. Явный запрос создания Excel/CSV/файла при наличии шаблонов
не принимается как completed без созданного файла; API ограниченно продолжает цикл.
Распознавание явного запроса по тексту не покрывает все формулировки; выбор
подходящего сценария по естественному языку всё ещё делает модель.

## Оформление и ограничения

Excel: название/фильтры, заголовки, ширины, перенос текста, закрепление,
автофильтр, числовой/процентный формат, жирная итоговая строка.
CSV: одна прямоугольная таблица с заголовками и опциональными итогами,
UTF-8 BOM, без оформления и вступительных строк.
Строки, похожие на формулы, записываются как текст, CSV защищается от формул.

Word продолжает работать через прежний create_report. Шаблоны Word, несколько
листов, JOIN, графики и произвольные формулы в этот вариант не включены.
Сценарии без report_template работают по прежней логике. Шаблоны не заменяют
все произвольные отчёты автоматически. Оригинальный XLSX в PostgreSQL является
сохранённым результатом; повторный запрос шаблона читает актуальное состояние БД.

## Установка

1. Выполнить database/init.sql в PostgreSQL приложения: добавится
   scenarios.report_template JSONB, существующие сценарии сохранятся.
2. Обновить API и settings.toml, пересобрать контейнер.
3. Импортировать oracle_serv/f101_page_237.sql.
   Вручную: обновить HTML GPT_SCENARIO_EDIT, JsScenarios, добавить JsTemplates
   из templates_region.sql как PL/SQL-регион после JsCommon/JsScenarios (sequence 74),
   с условием return nvl(ZGET_ROLE(), -1) = 0.
4. Настроить шаблон у нужного сценария или создать пример.

GPT_API и GPT_SCENARIOS менять для шаблонов не требуется: они передают JSON.
